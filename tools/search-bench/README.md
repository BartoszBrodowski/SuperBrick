# Picker retrieval benchmark

## Data and protocol

- `sample.json`: seeded (`20261110`) uniform sample of 100 visible, non-moved
  catalogue entries. No hand-picked easy/common-parts subset.
- `queries-v2.jsonl`: 500 descriptions independently generated by the requested
  `openai/gpt-6-luna` subagent: short, medium, detailed, informal and typo variants.
  The subagent saw part metadata, not search results or ranking code. V1 is kept
  for audit; V2 improves paraphrasing rather than wrapping official titles.
- Split by **part**, not query: 80 development parts / 400 descriptions and
  20 held-out parts / 100 descriptions. No held-out descriptions or failures
  were inspected for tuning. `frozen-profile.json` records the selection and
  query hash before held-out evaluation. The CLI refuses held-out grid searches.

These are **synthetic, metadata-derived** descriptions, not user studies or
image-grounded identification. They include niche printed/decorated parts and
some ambiguous queries. Five descriptions of one part are correlated; the test
set contains only 20 independent part identities. The generator reported two
detailed-query length violations; see `v2-provenance.json`. Do not overinterpret
the percentages as real-user accuracy.

## Results

| Dataset | Prior-weight baseline top 10 | Selected production top 10 | Production top 1 |
|---|---:|---:|---:|
| Development, 400 descriptions | 66.0% | 92.5% | 83.0% |
| Held-out, 100 descriptions | 66.0% | **84.0%** | 61.0% |

Held-out MRR@50 improves **0.358 → 0.672**. Production p95 query time in that
run was about **13 ms** (warm local index). The baseline uses the old weights
with the same new exact-ID and query-colour correctness fixes; it is not an
untouched old-binary comparison.

The selected adaptive profile preserves popularity/canonical preferences for
short common queries, but increases lexical/semantic influence for specific
descriptions. A purely semantic-heavy profile reached 96.75% development top 10
but substantially regressed the existing common-parts corpus; it was not shipped.
The selected profile retains **91.1% top 1 / 97.0% top 10** on that 168-query
legacy corpus. Full reports, including development-only grid comparisons, are
stored alongside this file. Held-out reports omit query/failure text.

## Reproduce (from `cad/`)

```sh
cargo run --release -p cad-cli -- search-bench \
  --queries tools/search-bench/queries-v2.jsonl --split dev --grid
cargo run --release -p cad-cli -- search-bench \
  --queries tools/search-bench/queries-v2.jsonl --split heldout --profile production
cargo run --release -p cad-cli -- search-bench \
  --queries tools/search-bench/queries-v2.jsonl --split heldout --profile baseline
```

Further tuning must use development data or a new held-out sample, not optimize
against these reported held-out results.
